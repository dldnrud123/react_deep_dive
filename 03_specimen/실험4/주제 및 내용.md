
## 주제 : Event Handler에서 처리해야 할 로직을 Effect로 구현한 뒤 리팩터링
[실험방법]
1. 결제 플래그 State(isSubmitting)를 변경하여 useEffect에서 결제 API를 실행하도록 작성 후 테스트.
2. useEffect와 불필요한 플래그 State를 제거하고, handleBuyClick 이벤트 핸들러 내부에서 직접 API를 호출하도록 리팩터링 후 테스트.

[실험결과]

1. 사용자의 클릭 의도와 실제 비동기 API 실행 로직이 물리적으로 분리되어, State 변경에 따른 추가 렌더링이 발생한 후에야 Effect가 동작함.
   컴포넌트 마운트나 뒤로가기/새로고침 시 잔여 State로 인해 의도치 않은 중복 결제 API가 호출될 위험이 존재함.

2. 유저 액션이 일어난 정확한 시점에 단일 흐름으로 비동기 작업이 수행되어 예측 가능성이 높아짐.
   플래그(isSubmitting) 감시를 위한 불필요한 Effect와 렌더링 단계를 제거하여 코드가 직관적으로 개선됨.
