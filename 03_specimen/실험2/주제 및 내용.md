
## 주제 : WebSocket 또는 EventListener mock 연결/cleanup 구현


# EventListener 실험

[실험방법]
1. 컴포넌트 열기 버튼을 눌러 이벤트를 실행한다.
2. 콘솔창을 열어 아무키를 입력해본다.
3. 컴포넌트 닫기 버튼을 눌러 이벤트를 종료한다.
4. cleanup을 지우고 1-2-3 을 순서대로 동일하게 동작해본다.

[실험결과]

- cleanup이 있을 때
1. 이벤트 실행 후 키 입력시 입력한 키 정보가 콘솔에 찍힘
2. 컴포넌트를 닫으면 클린업에 의해 이벤트가 언마운트 됨
3. 컨포넌트 닫고 키입력시 콘솔에 키정보가 안찍힘
4. 컨포넌트를 다시 열고 키정보를 입력 하면 콘솔에 다시 키 정보가 찍힘.

- cleanup이 없을 때
1. 이벤트 실행 후 키 입력시 입력한 키 정보가 콘솔에 찍힘
2. 컴포넌트를 닫아도 키 입력시 콘솔에 키정보가 동일하게 찍힘
3. 컨포넌트를 다시 열고 키정보를 입력 하면 콘솔에 다시 키 정보가 두번 찍힘.

# Mock WebSocket 연결 및 해제 실험

[실험방법]
1. 화면켜기 버튼을 눌러 화면을 킨다.
2. BTC 보기 버튼과 ETH 보기버튼을 번갈아서 눌리며 화면을 확인한다.
3. 화면끄기 버튼을 눌러 종료한다.
4. cleanup을 지우고 1-2-3 을 순서대로 동일하게 동작해본다.

[실험결과]

- cleanup이 있을 때
1. 화면켜기 버튼을 눌러 화면을 키면 BTC 금액이 노출된다.
2. BTC 보기 버튼과 ETH 보기버튼을 번갈아서 눌리면 BTC 금액과 ETH 금액이 번갈아서나옴.

- cleanup이 없을 때
1. 화면켜기 버튼을 누르지 않아도 화면이 켜져있음
2. BTC 보기 버튼과 ETH 보기버튼을 번갈아서 눌리면 소켓이 종료되지않아 BTC와 ETH 금액이 번갈아가면서 출력된다
3. 여러번 눌릴시 계속누적되어 누른만큼 화면을 갱신함.

[결론]

1. Cleanup 미작성 시 화면에서 컴포넌트가 사라지거나 deps가 바뀌어도 브라우저 메모리에 등록된 이벤트 리스너나 소켓 연결은 자동으로 사라지지 않는다. 
사용자가 페이지를 이동할 때마다 동일한 리스너가 N개로 증식하여 중복 실행 버그와 메모리 누수를 유발한다.

2. deps가 변경될 때 직전 Effect의 Cleanup 함수를 먼저 실행하여 기존 연결을 끊은 뒤, 새로운 Effect를 실행하여 새 연결을 맺는다.

3. StrictMode의 검증으로  Mount -> Unmount -> Mount 시뮬레이션을 통해 개발자가 Cleanup 코드를 누락했을 때 콘솔에 로그가 두 배로 찍히거나 소켓이 중복 생성되는 문제를 배포 전에 즉각 잡아낼 수 있다.
